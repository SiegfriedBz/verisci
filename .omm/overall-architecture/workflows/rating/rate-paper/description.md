rate-paper.ts: runRating and the rate-paper function (a singleton per request id, throttled outside local, a 300-minute budget, attempts 2, 5, 15, 30 and 60 minutes apart, 6 in all). It checks the request is pending on one of our contracts, cancels invalid-target a paper LabsTrail did not publish, then reads the R-KA's state and does only what is left: find the PDF link with the paper's title and abstract, read its text (a run's first failed read once more 15 s later), check its field with Flash-Lite, score it with one Gemini request per attempt until it answers, store and mint the R-KA, read the score back, and have the oracle fulfil. Outside the field, no text, too large, four bad reads, or two answers the scorer's check refuses cancel invalid-target; past 24 hours, expired. Once the oracle answers, it alerts on an orphan R-KA (alert-orphan): one stored, never minted, when it cancels the request expired, or one written for a request cancelled meanwhile or gone; and, when the contract's oracle changed mid-run, on what becomes of its R-KA (alert-oracle-moved): a minted one is recorded by a later run under the contract's oracle key unless the request is cancelled by hand meanwhile, a stored one past the maximum age only if its mint landed; for a settled request it sends one activity message (notify), looking the paper up first when the run never read it (find-paper), each from a step of its own.
